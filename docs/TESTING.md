# KERNOX 2.0 — Automated Verification & Testing Guide

**Project:** KERNOX 2.0: Android Resource Intelligence & Memory Reclamation Platform
**Target Environment:** Ubuntu 24.04 LTS (WSL 2 / Native Linux x86_64)
**Compiler:** GCC 13.3+ / Clang 18+ (`-std=c++20`)
**Build System:** CMake 3.25+ & Ninja

---

## 1. Testing Philosophy & Test Architecture

KERNOX 2.0 enforces a multi-tiered verification methodology:

1. **Zero External Dependencies for C++ Core:**
   Unit tests use [`tests/test_harness.hpp`](file:///e:/KERNOX%28OS%20CP%29/tests/test_harness.hpp), a lightweight, zero-overhead assertion framework (`KERNOX_ASSERT_*`). No heavy frameworks (GTest, Catch2) are required.
2. **Deterministic PRNG Validation:**
   Simulation engines and workload generators use fixed-seed Mersenne Twister PRNGs (`std::mt19937_64`), guaranteeing reproducible outcomes across builds and runs.
3. **Strict Domain Provenance Verification:**
   All datasets generated by the C++ engine carry explicit domain tags, validated by the Python test suite to ensure simulation data cannot be conflated with live Android hardware data.
4. **Resilient Subprocess and Mock Fixtures:**
   ADB parsing and Python subprocess execution are tested against static mock fixtures (`tests/fixtures/adb/` and `tools/analytics/tests/fixtures/`), preventing hardware or environment dependencies from causing test flakiness.

## 4. Execution Commands

### Run C++ Test Suite (Release Preset)
```bash
cmake --preset dev-release
ninja -C build/release
ctest --test-dir build/release --output-on-failure
```

### Run C++ Test Suite (Debug Preset)
```bash
cmake --preset dev-debug
ninja -C build/debug
ctest --test-dir build/debug --output-on-failure
```

### Run Python Test Suite
```bash
PYTHONPATH=tools/analytics/src ./.venv/bin/pytest tools/analytics/tests -v
```

### Run Full End-to-End Test & Smoke Script
```bash
./scripts/test.sh
```

### Run Complete End-to-End Demonstration Script
```bash
./scripts/demo_kernox.sh
```
