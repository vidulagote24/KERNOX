# KERNOX 2.0 — Phase F: Python Analytics & Visualization

## 1. Executive Summary

Phase F introduces a dedicated, non-invasive Python analytics and visualization layer into **KERNOX 2.0: Android & Linux Resource Intelligence Platform**. Positioned in `tools/analytics/`, this layer ingests raw experiment outputs and Android device observations generated by the authoritative C++20 core and transforms them into publication-quality visualizations and Markdown reports.

### Key Architectural Principles
- **Authoritative C++ Core**: The existing C++20 engine remains the sole authority for OS simulation, process lifecycle management, memory reclamation algorithms, workload generation, and ADB communication. Python does not duplicate simulation or reclamation algorithms.
- **Zero Build Coupling**: The C++ build system (`cmake`, `ninja`, `./scripts/test.sh`) remains 100% independent of Python. Python is neither required to compile nor to run KERNOX core binaries.
- **Strict Data Provenance**: Complete isolation is maintained between simulation datasets (`kernox_simulation`), real Android observations (`android_adb_observation`), and Linux host telemetry (`linux_proc_observation`).
- **Reproducible Analytics**: All metrics, statistical moments, and chart generation routines are deterministic and backed by automated unit tests.

## 4. Ingested Data Schemas

### 4.1 Experiment Comparison JSON (`kernox experiment compare --format json`)
Root fields:
- `scenario_name` (str)
- `seed` (int)
- `workload_fingerprint` (str)
- `total_capacity_bytes` (int)
- `policy_count` (int)
- `policy_results` (array of `ExperimentResult`)

Each `ExperimentResult` contains:
- `policy_name` (FIFO, LRU, Priority, ImportanceAware)
- `metrics.memory`: `total_capacity_bytes`, `initial_used_bytes`, `peak_used_bytes`, `final_used_bytes`, `average_utilization_ratio`, `total_reclaimed_bytes`, `pressure_events_moderate`, `pressure_events_critical`
- `metrics.processes`: `total_processes`, `processes_completed`, `processes_terminated_pressure`, `processes_survived`, `survival_rate`, and tier rates (`foreground_survival_rate`, `visible_survival_rate`, `service_survival_rate`, `background_survival_rate`, `cached_survival_rate`)
- `metrics.reclamation`: `reclamation_invocations`, `reclamation_successes`, `processes_reclaimed`, `average_reclaimed_per_victim_bytes`, `failed_allocations`, `no_eligible_victim_events`, `target_achievement_rate`
- `metrics.timing`: `simulated_duration_ticks`, `wall_clock_elapsed_microseconds`

### 4.2 Experiment Comparison CSV (`kernox experiment compare --format csv`)
Columns:
`scenario`, `seed`, `fingerprint`, `capacity_bytes`, `policy`, `reclaimed_bytes`, `processes_reclaimed`, `processes_survived`, `total_processes`, `survival_rate`, `fg_survival_rate`, `vis_survival_rate`, `svc_survival_rate`, `bg_survival_rate`, `cached_survival_rate`, `peak_used_bytes`, `final_used_bytes`, `failed_allocations`, `simulated_ticks`, `wall_clock_us`.

### 4.3 Android ADB Observation Snapshot (`kernox adb snapshot --format json`)
Root fields:
- `source`: `"android_adb_observation"` (Mandatory provenance tag)
- `collection_timestamp_epoch_ms` (int)
- `collection_duration_us` (int)
- `device_info`: `serial`, `state`, `manufacturer`, `model`, `product`, `device`, `android_release`, `sdk_version`
- `memory_snapshot.memory_metrics`: `total_ram_bytes`, `free_ram_bytes`, `available_ram_bytes`, `used_ram_bytes`, `cached_bytes`, `buffers_bytes`, `swap_total_bytes`, `swap_free_bytes`, `zram_physical_used_bytes`, `lost_ram_bytes`
- `processes`: array of observed processes with `pid`, `process_name`, `package_name`, `pss_bytes`, `rss_bytes`, `normalized_importance`, `oom_score_adj`, `confidence`

## 5. Metric Definitions and Units

Every derived metric is documented with explicit formulas, units, and denominators:

| Metric Name | Formula / Derivation | Unit | Denominator |
|---|---|:---:|---|
| **Peak Utilization** | $\text{peak\_used\_bytes} / \text{total\_capacity\_bytes} \times 100\%$ | % | Total memory capacity |
| **Final Utilization** | $\text{final\_used\_bytes} / \text{total\_capacity\_bytes} \times 100\%$ | % | Total memory capacity |
| **Reclaimed Ratio** | $\text{total\_reclaimed\_bytes} / \text{total\_capacity\_bytes} \times 100\%$ | % | Total memory capacity |
| **Process Survival Rate** | $\text{processes\_survived} / \text{total\_processes} \times 100\%$ | % | Total processes created |
| **Process Termination Rate**| $\text{processes\_terminated\_pressure} / \text{total\_processes} \times 100\%$ | % | Total processes created |
| **Tier Survival Rate** | $\text{tier\_processes\_survived} / \text{tier\_processes\_total} \times 100\%$ | % | Total processes in specific tier |
| **Reclamation Success Ratio**| $\text{reclamation\_successes} / \text{reclamation\_invocations} \times 100\%$ | % | Total reclamation invocations |
| **Android Used RAM %** | $\text{used\_ram\_bytes} / \text{total\_ram\_bytes} \times 100\%$ | % | Total physical RAM |
| **Android Available RAM %**| $\text{available\_ram\_bytes} / \text{total\_ram\_bytes} \times 100\%$ | % | Total physical RAM |
| **Android Swap Used %** | $(\text{swap\_total} - \text{swap\_free}) / \text{swap\_total} \times 100\%$ | % | Total swap space |
| **Wall-Clock Latency** | Direct measurement of host execution time | $\mu s$ | Real elapsed microseconds |
| **Simulated Duration** | Logical ticks advanced by simulation event loop | ticks | Pure virtual time units |

## 9. Scientific Boundaries & Limitations

1. **Synthetic Deterministic Workloads**: Experiment charts reflect deterministic synthetic workloads. They prove algorithmic properties under simulated conditions, not empirical Linux kernel benchmarks.
2. **Policy Invariants vs Eviction Behavior**: Policies that do not model Android priority or importance tiers (such as FIFO and LRU) select victims strictly based on arrival time or recency of access. A lower observed foreground survival rate under extreme memory pressure is the expected consequence of blind eviction order, not a bug or invariant violation. Foreground protection invariants apply exclusively to policies designed and configured to respect tier boundaries (such as `ImportanceAware`).
3. **Survivor Semantics**: Consistent with the C++ engine (`ExperimentRunner`), processes that complete their execution normally are counted as survivors (`processes_completed` $\subseteq$ `processes_survived`), never as reclamation victims.
4. **Non-Additive Memory Accounting**: In Linux and Android telemetry (`/proc/meminfo`), `MemAvailable` is an estimated metric that incorporates `MemFree` together with reclaimable page cache and slab memory. Adding Free RAM and Available RAM or stacking them as mutually exclusive slices is invalid accounting. Visualizations must present them as independent comparative measurements against Total RAM.
5. **Execution Latency vs Asymptotic Complexity**: Wall-clock duration measurements capture host CPU scheduling and runtime overhead for specific synthetic runs. They do not demonstrate or prove theoretical asymptotic algorithmic complexity $\mathcal{O}(n)$.
6. **Android Provenance & Environment Labeling**: Telemetry captured from `emulator-5554` reflects an Android Virtual Device (AVD) running under host QEMU/KVM emulation, not physical silicon. Provenance metadata explicitly records emulator status.
7. **Data Provenance Isolation**: Simulated datasets and real Android observations remain strictly isolated and must never be co-plotted or blended as equivalent metrics.
