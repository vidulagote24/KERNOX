# KERNOX 2.0 — Python Analytics & Visualization Layer

## 1. Overview

The `kernox_analytics` package is an isolated, non-invasive Python analytics and visualization layer built for **KERNOX 2.0: Android & Linux Resource Intelligence Platform**.

It ingests simulation experiment benchmarks generated by Phase D (`kernox_experiment`) and real-world Android telemetry snapshots captured by Phase E (`kernox_adb`), translating raw metrics into publication-quality charts and Markdown summary reports.

> **Architectural Boundary:**
> Python is strictly an analytics and visualization consumer. The authoritative source for Operating Systems simulation, process lifecycle management, memory reclamation algorithms, and Android telemetry collection remains the C++20 core engine.

---

## 2. Environment Setup & Installation

### Prerequisites
- Python 3.11+
- Virtual environment support (`python3 -m venv`)

### Virtual Environment Setup
From the repository root (`E:\KERNOX(OS CP)` or `/mnt/e/KERNOX(OS CP)` under WSL):

```bash
# 1. Create dedicated isolated virtual environment
python3 -m venv .venv

# 2. Activate virtual environment
# On Linux / WSL:
source .venv/bin/activate
# On Windows (PowerShell):
.\.venv\Scripts\Activate.ps1

# 3. Install dependencies
pip install -r tools/analytics/requirements.txt
```

### Dependencies (`requirements.txt`)
- `pandas>=2.2.0`: High-performance tabular data ingestion and manipulation
- `numpy>=1.26.0`: Numerical calculations and statistical moments
- `matplotlib>=3.8.0`: Publication-quality headless chart rendering
- `pytest>=8.0.0`: Deterministic unit testing harness

## 3. Command-Line Interface (CLI)

The package provides a unified CLI via `python -m kernox_analytics.cli`:

### 3.1 Schema & Provenance Validation (`validate`)
Validates single files or entire directories for RFC-compliant JSON/CSV structure, data sanity, and domain isolation:

```bash
PYTHONPATH=tools/analytics/src python3 -m kernox_analytics.cli validate \
  --input tools/analytics/examples/experiments
```

### 3.2 Experiment Analysis & Chart Generation (`analyze`)
Analyzes a multi-policy comparison run, evaluates policy tradeoffs, and generates charts:

```bash
PYTHONPATH=tools/analytics/src python3 -m kernox_analytics.cli analyze \
  --input tools/analytics/examples/experiments/high_pressure_comparison.json \
  --output tools/analytics/output
```

**Generated Visualizations:**
- `policy_comparison.png`: 4-panel comparison of Reclaimed Memory, Peak/Final Footprint, Survival Rate, and Foreground Protection.
- `process_survival.png`: Grouped bar chart comparing survival across Foreground, Visible, Service, Background, and Cached tiers.
- `memory_pressure.png`: Memory utilization bars against Moderate (75%) and Critical (90%) pressure thresholds (matching Phase C `reclaim::PressureThresholds`).
- `execution_performance.png`: Wall-clock host execution time ($\mu s$) vs simulated logical duration (ticks) as observed benchmark runtime.
- `experiment_summary.md`: Consolidated Markdown report with embedded figures.

### 3.3 Multi-Scenario Evaluation (`compare`)
Compares policy resilience across all 5 workload scenarios (`Normal`, `HighMemoryPressure`, `BackgroundHeavy`, `ForegroundProtection`, `Mixed`):

```bash
PYTHONPATH=tools/analytics/src python3 -m kernox_analytics.cli compare \
  --input tools/analytics/examples/experiments \
  --output tools/analytics/output
```

**Generated Visualization:**
- `scenario_comparison.png`: Cross-scenario evaluation of survival rates and reclaimed memory across all 5 scenarios.

### 3.4 Android Observation Telemetry (`android`)
Visualizes real-world Android device memory and process hierarchies:

```bash
PYTHONPATH=tools/analytics/src python3 -m kernox_analytics.cli android \
  --input tools/analytics/tests/fixtures/android_snapshot_fixture.json \
  --output tools/analytics/output
```

**Generated Visualizations:**
- `android/device_memory.png`: Android device RAM metrics (Used, Available, Free, Cached, Swap Used) with non-additive comparison against Total RAM.
- `android/process_memory.png`: Top monitored Android processes ranked by Proportional Set Size (PSS) with importance tier coloring.
- `android_summary.md`: Android observation summary report.

### 3.5 Automated Report Pipeline (`report`)
Auto-detects file type (simulation experiment or Android observation) and executes the complete analysis pipeline:

```bash
PYTHONPATH=tools/analytics/src python3 -m kernox_analytics.cli report \
  --input tools/analytics/examples/experiments/high_pressure_comparison.json \
  --output tools/analytics/output
```

## 4. Data Provenance & Domain Isolation

KERNOX enforces strict data provenance boundaries across three separate domains:
1. `kernox_simulation`: Generated by C++ simulation engines (`kernox_experiment`, `kernox_intel`, `kernox_reclaim`).
2. `android_adb_observation`: Captured passively from physical or emulated Android devices via `kernox_adb`.
3. `linux_proc_observation`: Real-time Linux host resource telemetry.

**Provenance Guarantees:**
- Datasets from different domains are never combined silently.
- Experiment loaders reject Android observation snapshots, and Android analyzers reject simulation datasets.
- Real Android PIDs (`AndroidPid`) are never passed to simulation termination routines.

## 5. Automated Verification & Testing

Run the full pytest suite (36 tests) without requiring Android hardware:

```bash
PYTHONPATH=tools/analytics/src pytest tools/analytics/tests -v
```

All tests use deterministic mock fixtures in `tools/analytics/tests/fixtures/` and execute offline in headless CI environments.
